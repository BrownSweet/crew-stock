# 公司与行业长期研究档案使用指南

> 本文保留原项目的人工试点设计。当前 Docker 产品及 v0.4 操作请阅读 [研究使用指南](RESEARCH_GUIDE.md)。

> 指南版本：`1.1`  
> 更新日期：2026-08-05  
> 当前阶段：设计已确认，适合人工试点；自动化采集尚未启用

## 1. 这套系统怎样使用

这不是一个输入股票代码后直接给出买卖结论的工具，而是一套持续积累证据、发现变化、辅助复盘的研究工作流。

日常使用分为三种模式：

| 模式 | 适合场景 | 当前状态 |
| --- | --- | --- |
| Codex 交互研究 | 建档、补充资料、分析一次事件、生成待确认判断 | 现在可用 |
| 用户资料提交 | 上传文章、截图、电话会记录、社交媒体内容和个人批注 | 现在可用 |
| Scheduled task | 每日采集、每周研究、每月逻辑审计 | 尚未创建，需先完成单公司试点 |

推荐顺序：

```text
选择试点公司
    ↓
建立公司、证券和行业对象
    ↓
通过 Longbridge MCP 采集首份只读基线
    ↓
人工检查事实、推测和缺口
    ↓
连续做 1–2 次增量更新
    ↓
确认模板稳定后再创建定时任务
```

## 2. 当前能做什么

目前可以直接让 Codex：

- 使用 Longbridge MCP 查询上市公司的公司资料、行情、财务、业务分部、机构预期、估值、监管文件、新闻、股东和行业数据；
- 规划一家公司与多个证券的归属关系，例如 Alphabet 公司对应 `GOOGL.US` 和 `GOOG.US`；
- 建立公司与行业的引用关系，不复制公司档案；
- 整理用户上传的原文、观点和批注；
- 从证据中提出供应链关系、管理层承诺、观点分类和研究判断；
- 把模型判断标记为待确认，不直接修改已确认的投资逻辑。

目前还不能直接依赖：

- Longbridge CLI 的无人值守采集，因为 CLI 授权和端点连通尚未验证；
- 自动 ID 分配，因为中央登记表和确定性分配脚本尚未建立；
- 自动去重、哈希、差异计算和采集水位，因为对应脚本尚未实现；
- Scheduled task，因为还没有完成首家公司模板和失败恢复验证。

## 3. 第一次使用：建立一家试点公司

### 第一步：选择研究对象

建议第一家只选一家公司，同时给出：

- 公司名称；
- 至少一个 Longbridge 证券代码；
- 研究目的；
- 重点关注的 3–5 个问题；
- 是否建立行业、供应链和公众人物档案。

证券代码格式：

| 市场 | 格式 | 示例 |
| --- | --- | --- |
| 美股 | `<代码>.US` | `AAPL.US` |
| 港股 | `<代码>.HK` | `700.HK` |
| 沪市 | `<代码>.SH` | `600519.SH` |
| 深市 | `<代码>.SZ` | `300750.SZ` |
| 新加坡 | `<代码>.SG` | `D05.SG` |

可以直接对 Codex 说：

```text
按照《关键设计.md》和《使用指南.md》，为苹果公司建立第一份人工试点档案。

证券代码：AAPL.US
研究目的：长期跟踪公司基本面和供应链风险
重点问题：
1. iPhone、服务和可穿戴设备的收入结构变化
2. 管理层对收入、毛利率和资本开支的指引
3. 关键供应商、代工厂和渠道的依赖关系
4. 市场一致预期发生了什么变化
5. 哪些证据可能证伪当前投资逻辑

建立公司、证券、行业和供应链对象，但先不要创建定时任务。
使用 Longbridge 只读能力；所有模型判断进入待确认状态。
```

如果一家公司有多个证券，仍只建立一个公司主体：

```text
为 Alphabet 建立一个公司主体，并将 GOOGL.US 和 GOOG.US 建成两个证券对象。
公司事实、财报和管理层内容只保存在公司主体；股权类别、投票权、价格和估值保存在证券对象。
```

### 第二步：让 Codex 先给出建档清单

首次建档不要立刻生成大量结论。先要求 Codex 输出：

- 拟创建的对象类型；
- 公司与证券的归属关系；
- 行业引用；
- 需要调用的 Longbridge 只读工具；
- Longbridge 无法提供的数据缺口；
- 准备创建的文件和目录；
- 需要用户确认的主观判断。

推荐提示词：

```text
先给我建档清单，不要写文件。
将内容分为：Longbridge 可获取、需要确定性程序处理、需要 LLM 分析、需要我提供或确认。
```

确认清单后再说：

```text
确认，按照清单创建人工试点档案。保留原始证据，不创建定时任务。
```

### 第三步：检查首份档案

至少检查以下内容：

1. 公司主体和证券是否被错误合并或重复创建；
2. 财务数字是否有原始来源、报告期和采集时间；
3. 事实、推测、市场情绪、外部观点和用户批注是否分开；
4. 供应链关系是否有方向、证据、权重理由和置信度；
5. 模型是否把新闻或人物影响力误当成事实正确性；
6. 投资逻辑变化是否仍处于待确认状态。

## 4. 日常怎样追加研究

### 4.1 查询一次最新变化

```text
使用 $longbridge:longbridge，对 AAPL.US 做一次只读增量检查。
只比较上次采集之后的新财务、指引、机构预期、监管文件和新闻。
先列事实变化，再列推测和市场情绪；没有实质变化就明确写“无实质变化”。
不要修改已确认投资逻辑。
```

### 4.2 整理新财报

```text
检查 AAPL.US 是否有新财报。
如有，保存原始数据并整理：关键财务变化、业务分部变化、公司指引、管理层承诺、预期差、反方证据和待确认问题。
同比、环比和利润率使用确定性计算，不让 LLM 心算。
```

### 4.3 对比管理层承诺

```text
对比苹果管理层过去四个报告期的公开承诺与实际结果。
每项承诺给出原始出处、目标期间、验证指标和当前状态。
不要把措辞变化直接判定为失信，先标记证据和解释空间。
```

### 4.4 更新行业和竞争对手

```text
更新存储行业本周变化，覆盖美光、SK 海力士和闪迪。
公司档案保持独立，行业档案只保存成员引用、共同指标、供需变化和竞争格局。
标出数据期间或会计口径不可比之处。
```

### 4.5 分析供应链冲击

```text
为苹果供应链建立一个情景：关键先进制程供应中断 20%，持续一个季度。
只使用有证据的关系边；模型提出依赖权重、置信度和理由。
输出直接影响、多级传导、缓冲因素和不可确定项，不预测股价。
```

### 4.6 添加公众人物观点

上传文章、截图或文字后，可以说：

```text
把这份内容作为用户提交保存。
识别发表人、发布时间、原始观点、涉及公司或行业、观点类型和上下文。
将原文、我的批注和模型抽取结果分开；不要把观点写入公司事实。
```

如果只是你的个人看法：

```text
这是我的主观批注，不是外部事实。请关联到苹果公司的供应链风险主题，状态保持待验证。
```

### 4.7 通过观点建立公司或行业档案

上传观点时不必先决定它属于哪个目录。Codex 可以先保存原文，再识别其中涉及的公司、证券、行业、事件和供应链关系。

一份观点可以同时关联多个对象，但原文只保存一次。例如关于 HBM 供需的观点，可以同时关联存储行业、美光、SK 海力士、AI 服务器行业及相关供应链关系。

处理规则：

1. 先创建 `sub-*` 保存原文、来源、上传时间和哈希；
2. 将公众人物观点抽取为 `opn-*`，用户自己的看法保存为 `user_annotation`；
3. 优先匹配已有 `cmp-*`、`sec-*` 和 `ind-*`；
4. 未匹配对象只生成 `pending_confirmation` 待建档候选；
5. 用户确认后，确定性程序分配正式 ID 并回填引用；
6. 使用 Longbridge 只读数据核验可以验证的事实声称；
7. 观点只能触发研究任务和待确认建议，不能直接修改公司事实或投资逻辑。

可以直接使用：

```text
把我上传的内容作为观点驱动归档处理。

请完成：
1. 保存原文，不改写原始内容；
2. 识别作者、发布时间、来源和观点类型；
3. 识别涉及的公司、证券、行业、事件和供应链关系；
4. 优先关联已有 ID；
5. 未建档对象只生成待确认候选，不自行分配正式 ID；
6. 使用 Longbridge 只读能力核验可验证的事实声称；
7. 分开输出原始观点、用户批注、支持证据、反方证据和模型推测；
8. 不修改已确认的公司事实、关系权重和投资逻辑。
```

## 5. 每次研究应产生什么

一次合格的运行应留下四类结果：

1. **原始证据**：Longbridge 返回内容或用户上传原文；
2. **确定性结果**：ID、哈希、去重结果、差异和数值计算；
3. **研究分析**：事实分类、解释、关系和待确认判断；
4. **运行记录**：调用了什么、参数是什么、何时采集、成功或失败、是否发生回退。

如果只留下总结而没有原始证据，这次研究不应进入长期档案。

## 6. Longbridge MCP、CLI 和 skill 怎样配合

### MCP

当前优先使用，适合：

- 在 Codex 对话里查询一家公司；
- 临时组合财务、预期、新闻和行业数据；
- 验证某个工具能否返回目标市场数据；
- 首家公司人工试点。

你不需要自己输入 MCP 工具名称，只需在提示词里说明“使用 Longbridge 只读能力”，Codex 按白名单选择工具。

### CLI

未来用于：

- 批量处理多家公司；
- 使用 `--format json` 保存可复现输出；
- 获取监管文件或新闻完整正文；
- 本地脚本、断点续跑和 Scheduled task。

CLI 使用前必须逐项确认安装、授权、网络连通、目标市场返回和日志目录权限。当前不能把 MCP 已授权等同于 CLI 已授权。

### skill

`$longbridge:longbridge` 是研究能力路由说明。它帮助 Codex 选择行情、财务、研究、新闻或财报专项能力，但实际证据仍来自 MCP 或 CLI。

## 7. 什么时候可以创建定时任务

满足以下条件后再启用：

- 已完成一家公司的基线档案；
- 已成功执行至少两次人工增量更新；
- ID 分配、哈希、去重和差异脚本已实现并验证；
- Longbridge CLI 或选定的 MCP 路径能在无人值守环境运行；
- 只读白名单实际接入任务执行器；
- 失败能留下记录且不会用旧数据冒充新数据；
- 用户已确认什么变化需要提醒。

建议启用顺序：

1. 每日只读采集；
2. 每周增量研究；
3. 新财报触发的深度任务；
4. 每月投资逻辑审计。

## 8. 使用中的硬性边界

- 不允许自动下单、撤单、改单或调仓；
- 不允许定时任务修改提醒、自选股、社区帖子或其他外部状态；
- 不允许 LLM 分配 ID、计算哈希或伪造缺失数字；
- 不允许无来源的供应链关系进入已确认图；
- 不允许人物观点直接覆盖公司事实；
- 不允许 Codex 自动确认投资逻辑变化；
- 不允许查询失败后静默换源；
- 不允许把研究报告包装成保证收益的荐股结论。

## 9. 推荐的下一步

当前最合理的下一步是选择一家试点公司，先生成“建档清单”，暂不创建定时任务。

需要提供的最少信息：

```text
公司名称：
证券代码：
研究目的：
最关注的三个问题：
是否同时建立行业档案：是/否
是否同时建立供应链图：是/否
需要跟踪的公众人物：可留空
```
